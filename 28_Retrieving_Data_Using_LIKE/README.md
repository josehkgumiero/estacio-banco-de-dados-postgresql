# Recuperando dados com o uso do operador LIKE
O projeto está disponível em: [Recuperando dados com o uso do operador LIKE](./Retrieving_Data_Using_LIKE.docx)

# Resumo
O documento apresenta um estudo detalhado sobre a utilização do operador LIKE no PostgreSQL, destacando sua importância para a realização de consultas que envolvem a busca por padrões em campos textuais. Diferentemente dos operadores relacionais tradicionais, que realizam comparações exatas entre valores, o operador LIKE permite localizar registros cujo conteúdo corresponda total ou parcialmente a um padrão de caracteres previamente definido. Essa funcionalidade é amplamente utilizada em sistemas corporativos, aplicações web, mecanismos de pesquisa, cadastros de clientes, consultas documentais e processos de análise de dados, nos quais frequentemente é necessário localizar informações sem conhecer exatamente o conteúdo completo armazenado no banco de dados. O documento enfatiza que o domínio desse operador constitui uma competência essencial para profissionais que trabalham com bancos de dados relacionais, pois possibilita construir consultas mais flexíveis e adaptáveis às diferentes necessidades dos usuários.

Inicialmente, o material explica que o operador LIKE e sua variação NOT LIKE são utilizados para realizar comparações baseadas em cadeias de caracteres. Para tornar essas comparações mais flexíveis, o PostgreSQL disponibiliza dois caracteres curinga (wildcards): o símbolo _ (underscore), que representa exatamente um único caractere desconhecido, e o símbolo %, que representa qualquer sequência de caracteres, independentemente de seu tamanho, inclusive nenhuma ocorrência. A combinação desses caracteres permite construir padrões extremamente variados, possibilitando localizar registros que contenham determinadas palavras, iniciem ou terminem com um conjunto específico de caracteres ou apresentem letras em posições definidas. Essa abordagem torna o operador LIKE uma das principais ferramentas para consultas textuais em SQL.

Na sequência, o documento apresenta diversos exemplos práticos utilizando a tabela ALUNO. O primeiro exemplo demonstra a utilização do padrão '%COSTA%' para localizar alunos cujo nome contenha a palavra "COSTA" em qualquer posição da cadeia de caracteres. Nesse caso, os símbolos % posicionados antes e depois da palavra permitem que qualquer sequência de caracteres exista tanto antes quanto depois da expressão pesquisada. Esse tipo de consulta é muito utilizado em pesquisas por sobrenomes, nomes de clientes, descrições de produtos, cidades e diversos outros campos textuais armazenados em bancos de dados relacionais.

Em seguida, o documento demonstra a utilização do caractere curinga _ para localizar registros cuja segunda posição do nome contenha a letra "A", utilizando o padrão '_A%'. Nesse exemplo, o primeiro caractere é representado pelo símbolo _, que aceita qualquer valor, enquanto o segundo caractere deve obrigatoriamente ser a letra "A". O símbolo %, por sua vez, representa todos os demais caracteres existentes após essa posição. Esse exemplo evidencia como o operador LIKE pode ser utilizado não apenas para localizar palavras completas, mas também para identificar padrões estruturais dentro de cadeias de caracteres, recurso bastante útil em validações, padronizações e consultas especializadas.

O documento também aborda o operador NOT LIKE, demonstrando sua utilização para recuperar registros que não correspondam a determinado padrão textual. Como exemplo, é apresentada uma consulta que retorna o nome e a data de nascimento dos alunos cujo nome não contenha a palavra "MARIA" em nenhuma posição. Essa funcionalidade é especialmente útil quando se deseja excluir registros que possuam determinada característica textual, permitindo construir filtros negativos de forma simples e eficiente. Além disso, é apresentado um exemplo envolvendo funções de agregação, no qual o operador LIKE é utilizado juntamente com a função COUNT(*) para contabilizar quantos alunos possuem endereço de e-mail pertencente ao domínio Gmail, utilizando o padrão '%@GMAIL.%'. Esse exemplo demonstra que o operador LIKE pode ser combinado com diferentes recursos da linguagem SQL para produzir consultas analíticas mais completas e úteis em diversos contextos organizacionais.

Ao longo do material, observa-se que o operador LIKE representa um recurso indispensável para consultas envolvendo informações textuais. Sua capacidade de trabalhar com padrões, aliada à utilização de caracteres curinga e à possibilidade de integração com funções de agregação e operadores lógicos, permite desenvolver consultas mais eficientes, flexíveis e alinhadas às necessidades reais das aplicações. Dessa forma, o documento estabelece uma base sólida para o estudo de técnicas mais avançadas de pesquisa textual em bancos de dados relacionais, contribuindo para o desenvolvimento de soluções capazes de manipular informações de maneira precisa e organizada.

# Conclusão

O estudo do operador LIKE evidencia sua importância como um dos principais recursos da linguagem SQL para realização de pesquisas baseadas em padrões de texto. Diferentemente das comparações exatas realizadas pelos operadores relacionais convencionais, o LIKE oferece maior flexibilidade ao permitir localizar registros que contenham determinados caracteres, palavras ou sequências em posições específicas dentro de uma cadeia textual. Essa característica torna o operador indispensável para sistemas que realizam pesquisas por nomes, endereços, documentos, produtos, e-mails e diversas outras informações armazenadas em formato textual.

O documento demonstra que a utilização dos caracteres curingas % e _ amplia significativamente as possibilidades de construção das consultas. Enquanto o símbolo % permite representar qualquer quantidade de caracteres, o caractere _ substitui exatamente um único caractere desconhecido, possibilitando desenvolver filtros bastante específicos ou extremamente abrangentes conforme a necessidade da aplicação. Além disso, a utilização da versão NOT LIKE permite implementar filtros negativos, recuperando registros que não correspondem aos padrões definidos e aumentando ainda mais a flexibilidade das consultas SQL.

Outro aspecto relevante apresentado pelo material é a possibilidade de integrar o operador LIKE com outros recursos da linguagem SQL, como funções de agregação e cláusulas de filtragem. O exemplo que utiliza a função COUNT(*) para contabilizar usuários com contas de e-mail do domínio Gmail demonstra que pesquisas textuais podem ser combinadas com operações estatísticas para produzir indicadores úteis em processos de análise de dados, auditoria, geração de relatórios e Business Intelligence. Essa integração evidencia que o operador LIKE não se limita à simples recuperação de registros, mas também contribui para análises quantitativas e geração de informações estratégicas diretamente no banco de dados.

Em síntese, o documento estabelece uma base sólida para o uso do operador LIKE no PostgreSQL, demonstrando que a pesquisa por padrões textuais representa uma funcionalidade indispensável em bancos de dados relacionais modernos. O domínio desse operador prepara o profissional para desenvolver consultas mais sofisticadas, eficientes e alinhadas às necessidades de sistemas corporativos, além de servir como fundamento para o aprendizado de recursos mais avançados relacionados à pesquisa textual, expressões regulares, funções de manipulação de cadeias de caracteres e otimização de consultas SQL. Dessa forma, compreender corretamente o funcionamento do LIKE contribui significativamente para o desenvolvimento de aplicações mais robustas e para o aprimoramento das competências em gerenciamento e análise de dados.
