# Tratativa para Tabelas Relacionadas
O projeto está disponível em: [Tratativa para Tabelas Relacionadas](./Related_Tables_Handling.docx)
# Resumo
Este material apresenta os principais conceitos relacionados ao tratamento de tabelas vinculadas por chaves estrangeiras no PostgreSQL, enfatizando a importância da integridade referencial para garantir a consistência e a organização dos dados em bancos de dados relacionais. O documento explica que as chaves estrangeiras estabelecem relacionamentos entre tabelas, permitindo que registros de uma tabela façam referência às chaves primárias de outra, formando vínculos que asseguram a validade das informações armazenadas. Além de demonstrar como esses relacionamentos são criados, o conteúdo destaca que compreender sua manutenção é fundamental para realizar alterações estruturais sem comprometer a integridade do banco de dados.

Na sequência, o documento apresenta uma abordagem para a criação e modificação de tabelas relacionadas, utilizando como exemplo as tabelas NIVEL e CURSO. Inicialmente, é explicado que o relacionamento entre essas tabelas pode ser definido diretamente durante a criação da tabela por meio da cláusula FOREIGN KEY. Entretanto, o material demonstra que também é possível criar as tabelas de forma independente e, posteriormente, adicionar a restrição de chave estrangeira utilizando o comando ALTER TABLE, oferecendo maior flexibilidade durante o processo de desenvolvimento e evolução do banco de dados. O exemplo apresentado ilustra a inclusão da chave estrangeira após a criação das tabelas, evidenciando diferentes estratégias para implementação dos relacionamentos.

O conteúdo também aborda os cuidados necessários ao manipular tabelas relacionadas, destacando que a definição de uma chave estrangeira estabelece uma dependência entre as tabelas envolvidas. Como consequência, determinadas operações de alteração ou exclusão podem ser impedidas pelo Sistema Gerenciador de Banco de Dados caso representem risco à integridade referencial. O documento explica que, mesmo quando um comando SQL está sintaticamente correto, o PostgreSQL prioriza a consistência dos dados e bloqueia operações que possam resultar em referências inválidas ou registros órfãos, preservando a integridade do banco de dados durante todo o seu ciclo de vida.

Por fim, é apresentado um exemplo envolvendo a tentativa de remoção da tabela NIVEL, que possui relacionamento com a tabela CURSO. O documento demonstra que a execução do comando DROP TABLE NIVEL gera uma mensagem de erro devido à existência de uma chave estrangeira dependente. Para contornar essa situação, são discutidas duas alternativas: remover manualmente todas as dependências existentes antes da exclusão da tabela ou utilizar o comando DROP TABLE ... CASCADE, que realiza automaticamente a remoção das dependências associadas. Dessa forma, o material evidencia o funcionamento dos mecanismos de proteção do PostgreSQL e reforça a importância de compreender os impactos das operações realizadas sobre tabelas relacionadas.
# Conclusão

O conteúdo apresentado demonstra que o gerenciamento de tabelas relacionadas constitui um dos aspectos mais importantes da administração de bancos de dados relacionais, uma vez que os relacionamentos estabelecidos por meio de chaves estrangeiras garantem a integridade referencial e asseguram a consistência das informações armazenadas. A correta definição dessas relações permite que diferentes tabelas compartilhem informações de maneira organizada, reduzindo redundâncias e preservando a confiabilidade dos dados utilizados pelas aplicações.

O estudo evidencia que a criação de relacionamentos pode ser realizada tanto durante a definição inicial das tabelas quanto posteriormente, utilizando o comando ALTER TABLE para adicionar restrições de chave estrangeira. Essa flexibilidade facilita a evolução dos projetos de banco de dados, permitindo que novas dependências sejam incorporadas conforme surgem novos requisitos de negócio. Ao mesmo tempo, o documento demonstra que qualquer alteração estrutural envolvendo tabelas relacionadas deve considerar cuidadosamente as dependências existentes, evitando impactos negativos sobre a integridade dos dados.

Outro aspecto de grande relevância abordado é o mecanismo de proteção implementado pelo PostgreSQL durante operações de exclusão. Ao impedir automaticamente a remoção de tabelas que possuem dependências ativas, o sistema evita que registros fiquem sem referência ou que relacionamentos sejam quebrados, preservando a consistência do banco de dados. O estudo do comando DROP TABLE ... CASCADE demonstra que, embora o PostgreSQL ofereça recursos para remover automaticamente essas dependências, sua utilização deve ocorrer com cautela, pois a exclusão em cascata pode remover diversos objetos relacionados de forma irreversível.

Em conjunto, os conceitos apresentados fornecem uma base sólida para compreender como o PostgreSQL administra relacionamentos entre tabelas e protege a integridade referencial durante operações de criação, alteração e exclusão de objetos. O domínio desses mecanismos é essencial para desenvolvedores e administradores de bancos de dados, permitindo projetar estruturas relacionais consistentes, realizar modificações de forma segura e compreender os impactos das dependências existentes em ambientes reais de banco de dados.
