# Projeto junções internas
O projeto está disponível em: [Projeto junções internas](./Internal_Junctions_Project.docx)

# Resumo
O material apresenta um projeto prático sobre junções internas (INNER JOIN) no PostgreSQL utilizando um banco de dados que representa o funcionamento de um museu. O objetivo principal é consolidar os conhecimentos sobre relacionamentos entre tabelas por meio da construção de consultas SQL capazes de integrar informações provenientes de diferentes entidades do banco de dados. Inicialmente, o documento apresenta o modelo lógico do minimundo MUSEU, composto por tabelas como AUTORES, OBRAS, PINTURAS, ESCULTURAS, SALÕES, FUNCIONÁRIOS, TURNOS e ALOCAÇÕES, evidenciando uma estrutura relacional semelhante à encontrada em sistemas corporativos reais. Em seguida, são fornecidas orientações para criação do banco de dados, execução do script e validação da estrutura criada no PGAdmin4.

Na sequência, o material apresenta o script completo de criação do banco de dados. São definidas todas as tabelas necessárias para representar as entidades do museu, incluindo autores, obras, pinturas, esculturas, funcionários, turnos, salões e alocações. Cada tabela possui sua respectiva chave primária e atributos específicos, permitindo modelar informações relacionadas ao acervo artístico, aos espaços de exposição e à equipe responsável pelo funcionamento do museu. Posteriormente, o documento insere diversos registros de exemplo, simulando um ambiente real de trabalho contendo autores de diferentes nacionalidades, obras produzidas em diferentes períodos históricos, pinturas, esculturas, funcionários, turnos de trabalho e distribuição de colaboradores pelos salões do museu.

Além da criação das tabelas e inserção dos dados, o documento estabelece os relacionamentos entre as entidades por meio de diversas chaves estrangeiras. As tabelas PINTURAS e ESCULTURAS são relacionadas à tabela OBRAS, enquanto OBRAS estabelece vínculos com AUTORES e SALÕES. Da mesma forma, ALOCAÇÕES relaciona funcionários aos salões, e FUNCIONÁRIOS mantém relacionamento com TURNOS. Essa estrutura evidencia a aplicação dos princípios de integridade referencial do modelo relacional, garantindo consistência entre os registros armazenados e possibilitando a realização de consultas envolvendo múltiplas tabelas simultaneamente.

Após a preparação da base de dados, o material apresenta uma série de consultas SQL utilizando INNER JOIN. O primeiro exemplo recupera todas as informações dos autores juntamente com suas respectivas obras, demonstrando a junção entre as tabelas AUTORES e OBRAS. Em seguida, são desenvolvidas consultas que retornam apenas obras produzidas entre determinados anos, obras localizadas em salões específicos e autores que efetivamente possuem obras cadastradas. Esses exemplos demonstram como o INNER JOIN permite combinar informações distribuídas em diferentes tabelas, retornando apenas registros que possuem relacionamento válido entre si.

O conteúdo evolui para consultas envolvendo três ou mais tabelas simultaneamente. São apresentadas consultas capazes de listar autores, nacionalidades, títulos das obras e estilos das pinturas, integrando informações provenientes das tabelas AUTORES, OBRAS e PINTURAS. Outro exemplo recupera apenas obras do autor Pablo Picasso localizadas no terceiro andar do museu, utilizando simultaneamente as tabelas AUTORES, OBRAS e SALÕES. Essas consultas demonstram como sucessivas operações de INNER JOIN permitem construir relatórios detalhados e altamente específicos, atendendo diferentes necessidades de análise e recuperação de informações.

Por fim, o documento compara duas formas distintas de realizar junções entre tabelas que compartilham uma coluna de mesmo nome. Inicialmente, é utilizada a cláusula USING para relacionar as tabelas OBRAS e PINTURAS por meio da coluna CODIGO. Em seguida, é apresentada a mesma consulta utilizando a sintaxe tradicional baseada na cláusula ON. O material demonstra que ambas produzem exatamente o mesmo resultado, diferenciando-se apenas pela forma de escrita da consulta. Dessa maneira, o projeto consolida os principais conceitos relacionados ao uso profissional das junções internas no PostgreSQL, mostrando diferentes estratégias para integrar informações armazenadas em múltiplas tabelas de um banco de dados relacional.

# Conclusão

O projeto prático sobre junções internas representa uma importante etapa no aprendizado da linguagem SQL aplicada ao PostgreSQL, pois demonstra como integrar informações distribuídas em diferentes tabelas por meio do uso do INNER JOIN. Ao utilizar um banco de dados que simula o funcionamento de um museu, o material aproxima o estudante de situações encontradas em ambientes reais, evidenciando que praticamente todas as consultas desenvolvidas em sistemas corporativos dependem da combinação de dados provenientes de diversas entidades relacionadas.

Ao longo do conteúdo, observa-se que a construção de um banco de dados completo, contendo tabelas, registros e relacionamentos definidos por chaves primárias e estrangeiras, constitui a base para a realização de consultas eficientes e consistentes. A utilização de restrições de integridade referencial garante que apenas relacionamentos válidos sejam estabelecidos entre os registros, permitindo que as operações de INNER JOIN recuperem informações corretas e coerentes durante a execução das consultas SQL.

Outro aspecto relevante apresentado no projeto é a evolução gradual da complexidade das consultas. Inicialmente, são realizadas junções entre apenas duas tabelas e, posteriormente, consultas envolvendo três ou mais tabelas simultaneamente, combinando informações sobre autores, obras, pinturas, salões e demais entidades do banco de dados. Essa progressão demonstra que o INNER JOIN é um recurso altamente flexível, capaz de integrar grandes quantidades de informações e produzir resultados detalhados para diferentes necessidades de análise, geração de relatórios e suporte à tomada de decisão.

O material também evidencia boas práticas de desenvolvimento ao apresentar diferentes formas de implementação das junções internas, utilizando tanto a cláusula ON quanto a cláusula USING. Essa comparação permite compreender que ambas as abordagens produzem resultados equivalentes quando corretamente aplicadas, oferecendo ao desenvolvedor alternativas para escrever consultas mais legíveis, organizadas e adequadas ao contexto de cada aplicação. O domínio dessas sintaxes contribui significativamente para a produção de código SQL mais limpo, reutilizável e de fácil manutenção.

Em síntese, o projeto demonstra que o INNER JOIN constitui um dos recursos mais importantes da linguagem SQL para bancos de dados relacionais. A capacidade de integrar informações provenientes de diferentes tabelas permite construir consultas robustas, eliminar redundâncias e produzir informações consolidadas que refletem com precisão a realidade armazenada no banco de dados. Dessa forma, o domínio das junções internas representa uma competência essencial para desenvolvedores, administradores de banco de dados, analistas de dados, engenheiros de dados e demais profissionais que atuam com sistemas de informação e análise de dados em ambientes corporativos.
