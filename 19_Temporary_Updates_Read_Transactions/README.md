# Atualização Temporária e Transação de Leitura
O projeto está disponível em: [Transações no PostgreSQL](./Temporary_Updates_Read_Transactions.docx)

# Resumo
O documento aborda dois conceitos fundamentais do PostgreSQL e dos bancos de dados relacionais: atualização temporária e transação de leitura (READ ONLY). Inicialmente, explica que as transações são mecanismos responsáveis por garantir a integridade, a consistência e a confiabilidade dos dados quando diversas operações são executadas simultaneamente. Durante a execução de uma transação, alterações realizadas por comandos de atualização permanecem temporárias até que sejam confirmadas, evitando que outras transações visualizem dados ainda não definitivos.

Em seguida, o material apresenta o conceito de atualização temporária por meio de um exemplo envolvendo comandos BEGIN, UPDATE, SAVEPOINT, ROLLBACK TO SAVEPOINT e COMMIT. O exemplo demonstra que uma transação pode realizar modificações parciais e, caso seja necessário, desfazer apenas parte dessas alterações utilizando pontos de salvamento (savepoints), preservando as demais operações já executadas. Além disso, evidencia que consultas realizadas por outras aplicações continuam visualizando os dados originais enquanto a transação não for confirmada, evitando inconsistências e impedindo que informações temporárias sejam disponibilizadas para outros usuários.

Na sequência, o documento explica o funcionamento das transações de leitura, destacando a diferença entre os modos READ ONLY e READ WRITE. É apresentado o comando SET TRANSACTION como mecanismo para definir o tipo da transação, ressaltando que, no PostgreSQL, o comportamento padrão é READ WRITE. Também é demonstrado, por meio de um exemplo prático, que uma transação configurada como READ ONLY permite apenas consultas aos dados, impedindo a execução de comandos que alterem o banco de dados, como INSERT, UPDATE e DELETE. Caso uma tentativa de atualização seja realizada, o sistema gerenciador de banco de dados retorna uma mensagem de erro, preservando a integridade da transação e garantindo que nenhuma modificação seja aplicada.

# Conclusão

O estudo evidencia que o controle de transações é um dos principais mecanismos responsáveis por garantir a segurança, a consistência e a confiabilidade das informações armazenadas em bancos de dados relacionais. O conceito de atualização temporária demonstra que alterações realizadas dentro de uma transação permanecem isoladas até sua confirmação definitiva, impedindo que outros usuários visualizem dados que ainda podem ser desfeitos por meio de um ROLLBACK. Esse comportamento preserva a integridade dos dados e evita problemas decorrentes de leituras inconsistentes durante operações concorrentes.

Além disso, a utilização de pontos de salvamento (SAVEPOINT) amplia a flexibilidade das transações, permitindo desfazer apenas parte das alterações executadas sem comprometer todo o processamento realizado anteriormente. Esse recurso torna as transações mais robustas e facilita o tratamento de erros em operações complexas, reduzindo riscos de perda de informações e proporcionando maior controle sobre o processo de manipulação dos dados.

O documento também reforça a importância das transações de leitura, que oferecem um ambiente seguro para consultas em situações nas quais nenhuma modificação deve ser realizada. Ao utilizar o modo READ ONLY, o PostgreSQL impede qualquer tentativa de alteração nos dados, garantindo que consultas possam ser executadas de forma confiável e sem riscos de modificações acidentais. Essa característica é especialmente útil em atividades de auditoria, geração de relatórios, análises estatísticas e consultas gerenciais, onde a integridade das informações deve ser preservada integralmente.

Por fim, conclui-se que os conceitos de atualização temporária, isolamento entre transações, controle por savepoints e definição do modo de leitura constituem recursos essenciais para o funcionamento eficiente do PostgreSQL. Esses mecanismos trabalham de forma integrada para assegurar que operações concorrentes sejam executadas com confiabilidade, mantendo a consistência dos dados, reduzindo conflitos entre usuários e proporcionando um ambiente de banco de dados seguro, estável e adequado para aplicações corporativas que exigem elevado nível de integridade e disponibilidade das informações.
