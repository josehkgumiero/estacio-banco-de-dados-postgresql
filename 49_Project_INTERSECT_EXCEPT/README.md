# Projeto operadores INTERSECT e EXCEPT
O projeto está disponível em: [Projeto operadores INTERSECT e EXCEPT](./Project_INTERSECT_EXCEPT.docx)

# Resumo
O material apresenta um projeto prático sobre os operadores de conjunto INTERSECT e EXCEPT no PostgreSQL utilizando o banco de dados do museu como ambiente para aplicação dos conceitos estudados anteriormente. O objetivo principal consiste em consolidar o conhecimento sobre operações de interseção e diferença entre conjuntos por meio da elaboração de consultas SQL voltadas à recuperação de informações específicas sobre autores, obras, pinturas e esculturas. Inicialmente, o documento apresenta o modelo lógico do banco de dados do museu e propõe um roteiro composto por cinco exercícios que exploram a identificação de autores com ou sem obras cadastradas, autores que produzem apenas pinturas, apenas esculturas e artistas especializados em um único tipo de obra. Essas atividades demonstram a aplicação prática dos operadores de conjunto em situações semelhantes às encontradas em sistemas corporativos e aplicações de análise de dados.

A primeira atividade utiliza o operador EXCEPT para identificar os autores cadastrados que não possuem qualquer obra exposta no museu. A consulta recupera inicialmente todos os códigos existentes na tabela AUTORES e, em seguida, remove aqueles que aparecem como autores na tabela OBRAS. Como resultado, permanecem apenas os registros dos artistas que ainda não possuem obras cadastradas no acervo do museu. Esse exemplo demonstra claramente o funcionamento do operador EXCEPT como implementação da operação de diferença entre conjuntos, permitindo localizar registros exclusivos da primeira consulta.

Na sequência, o projeto apresenta uma consulta utilizando o operador INTERSECT para identificar os autores que efetivamente possuem obras expostas. A consulta compara os códigos existentes na tabela AUTORES com os códigos de autores presentes na tabela OBRAS, retornando apenas os registros comuns aos dois conjuntos. Essa operação representa a aplicação prática da interseção entre conjuntos, permitindo recuperar exclusivamente os autores que possuem relacionamento com obras cadastradas no banco de dados.

O material evolui para consultas mais sofisticadas envolvendo simultaneamente as tabelas OBRAS, PINTURAS e ESCULTURAS. Inicialmente, utiliza-se EXCEPT para recuperar os autores que possuem pinturas, removendo aqueles que também possuem esculturas. Em seguida, é apresentada a operação inversa, responsável por identificar os autores que possuem apenas esculturas, excluindo aqueles que também produzem pinturas. Essas consultas combinam operações de junção (INNER JOIN) com operadores de conjunto, demonstrando que diferentes recursos da linguagem SQL podem ser integrados para produzir análises mais específicas e detalhadas.

Posteriormente, o documento apresenta uma consulta que reúne os autores especializados em apenas um tipo de obra artística. Para isso, são utilizadas duas operações EXCEPT independentes, responsáveis por identificar autores exclusivos de pinturas e autores exclusivos de esculturas. Em seguida, os dois resultados são combinados utilizando o operador UNION, formando um único conjunto contendo todos os artistas que trabalham exclusivamente com um único tipo de produção artística. Esse exemplo evidencia a integração entre diferentes operadores de conjunto para resolver problemas mais complexos de recuperação de informações.

Por fim, o projeto apresenta uma consulta complementar utilizando o operador INTERSECT para identificar os autores que possuem simultaneamente pinturas e esculturas cadastradas no museu. A consulta realiza duas junções independentes entre OBRAS e PINTURAS e entre OBRAS e ESCULTURAS, aplicando posteriormente a operação de interseção para recuperar apenas os autores presentes nos dois conjuntos. Esse exemplo demonstra que o operador INTERSECT também pode ser aplicado em consultas envolvendo múltiplas tabelas e junções, ampliando significativamente as possibilidades de análise em bancos de dados relacionais.

# Conclusão
O projeto prático sobre os operadores INTERSECT e EXCEPT consolida os principais conceitos relacionados às operações de conjunto na linguagem SQL, demonstrando como esses recursos podem ser empregados para comparar, diferenciar e identificar registros pertencentes a diferentes conjuntos de dados. Utilizando o banco de dados do museu como cenário de aplicação, o material evidencia que esses operadores representam ferramentas extremamente úteis para recuperação seletiva de informações, permitindo resolver problemas que seriam significativamente mais complexos utilizando apenas filtros tradicionais ou operações de junção.

Ao longo do conteúdo, observa-se que o operador EXCEPT desempenha papel fundamental na identificação de registros exclusivos de determinado conjunto. Os exemplos envolvendo autores sem obras, autores que possuem apenas pinturas e autores que possuem apenas esculturas demonstram claramente sua capacidade de eliminar elementos pertencentes a conjuntos específicos, tornando esse operador especialmente útil em auditorias de dados, validação cadastral, controle de integridade e processos de análise comparativa entre diferentes bases de informações. 

O operador INTERSECT, por sua vez, evidencia sua importância ao identificar registros comuns entre diferentes consultas. Os exemplos apresentados mostram como localizar autores que possuem obras cadastradas e artistas que produzem simultaneamente pinturas e esculturas, ilustrando aplicações típicas de interseção de conjuntos em bancos de dados relacionais. Esse recurso é amplamente empregado em integração de sistemas, cruzamento de informações, consolidação de cadastros e elaboração de relatórios analíticos que exigem a identificação de elementos compartilhados entre diferentes fontes de dados. 

Outro aspecto relevante do projeto é a demonstração da integração entre diferentes recursos da linguagem SQL. As consultas desenvolvidas combinam operadores de conjunto com INNER JOIN e UNION, evidenciando que soluções complexas podem ser construídas a partir da composição de múltiplas funcionalidades da linguagem. Essa abordagem amplia significativamente a capacidade de análise dos dados e permite desenvolver consultas mais organizadas, reutilizáveis e adequadas às necessidades encontradas em sistemas corporativos modernos.

Em síntese, o projeto demonstra que os operadores INTERSECT e EXCEPT constituem recursos indispensáveis para comparação e análise de conjuntos de dados em bancos relacionais. Sua utilização, aliada às operações de junção e aos demais operadores de conjunto, permite desenvolver consultas robustas, eficientes e altamente flexíveis para recuperação de informações específicas. O domínio dessas técnicas representa uma competência essencial para desenvolvedores, administradores de banco de dados, engenheiros de dados, analistas de dados e demais profissionais que atuam com sistemas de informação e soluções orientadas por dados.
