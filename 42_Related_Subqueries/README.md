# Subconsultas correlatas
O projeto está disponível em: [Subconsultas correlatas](./Related_Subqueries.docx)

# Resumo
O material apresenta o conceito de subconsultas correlatas no PostgreSQL, demonstrando como esse tipo especial de subconsulta permite relacionar dinamicamente a consulta interna com cada registro processado pela consulta principal. Diferentemente das subconsultas aninhadas convencionais, que são executadas apenas uma vez e fornecem um único resultado para a consulta externa, as subconsultas correlatas utilizam valores provenientes da própria consulta principal, sendo executadas repetidamente para cada linha analisada. Essa característica torna esse recurso especialmente útil para resolver problemas que dependem do contexto específico de cada registro, possibilitando análises mais precisas e sofisticadas em bancos de dados relacionais.

O primeiro exemplo apresentado busca identificar os funcionários cujo salário seja superior à média salarial dos colaboradores pertencentes ao mesmo departamento. Para isso, a consulta principal percorre cada funcionário da tabela FUNCIONARIO, enquanto a subconsulta calcula dinamicamente a média salarial apenas dos funcionários que pertencem ao mesmo departamento do colaborador analisado. Essa relação é estabelecida por meio da condição WHERE CODIGODEPARTAMENTO = F.CODIGODEPARTAMENTO, na qual o alias F representa a linha atualmente processada pela consulta externa. Dessa forma, a média salarial deixa de ser global e passa a ser calculada individualmente para cada departamento, tornando a análise mais específica e contextualizada.

Na sequência, o documento demonstra que essa mesma consulta pode ser implementada utilizando uma estratégia alternativa baseada em junção. Nesse caso, uma subconsulta realiza previamente o agrupamento dos funcionários por departamento utilizando GROUP BY e calcula a média salarial de cada setor. Posteriormente, a consulta principal realiza um JOIN entre a tabela FUNCIONARIO e o resultado produzido pela subconsulta, permitindo comparar o salário de cada funcionário com a média correspondente ao seu departamento. O material destaca que ambas as abordagens produzem exatamente o mesmo resultado, oferecendo diferentes possibilidades de implementação conforme critérios de desempenho, clareza e organização do código SQL.

Além das consultas de seleção, o conteúdo demonstra que subconsultas correlatas também podem ser utilizadas em operações de atualização de dados. Como exemplo, é apresentada uma situação em que todos os funcionários de um mesmo departamento devem passar a receber o maior salário existente dentro do próprio setor. Para realizar essa atualização, a instrução UPDATE percorre todos os registros da tabela FUNCIONARIO e utiliza uma subconsulta correlata para recuperar, individualmente para cada departamento, o maior salário existente naquele grupo por meio da função MAX(). O valor retornado pela subconsulta é então utilizado para atualizar o salário do funcionário correspondente.

O documento ressalta ainda que a atualização é aplicada apenas aos funcionários que possuem departamento associado, utilizando a condição WHERE F.CODIGODEPARTAMENTO IS NOT NULL. Dessa forma, colaboradores que ainda não estão vinculados a qualquer departamento permanecem com seus salários inalterados, preservando a integridade dos dados armazenados no banco de dados. Esse exemplo evidencia que subconsultas correlatas podem ser empregadas tanto em consultas de recuperação quanto em operações de manipulação de dados, ampliando significativamente as possibilidades oferecidas pela linguagem SQL para resolução de problemas complexos em ambientes corporativos.

# Conclusão
O estudo sobre subconsultas correlatas representa uma evolução importante no domínio da linguagem SQL, demonstrando como consultas podem ser construídas de forma dinâmica a partir dos próprios registros processados pela consulta principal. Ao contrário das subconsultas aninhadas tradicionais, executadas apenas uma vez, as subconsultas correlatas são reavaliadas para cada linha retornada pela consulta externa, permitindo realizar comparações individualizadas e produzir resultados mais específicos conforme o contexto de cada registro. Essa característica amplia significativamente a capacidade analítica dos bancos de dados relacionais e possibilita resolver problemas que exigem lógica mais sofisticada.

Ao longo do material, observa-se que as subconsultas correlatas são especialmente úteis em situações que envolvem cálculos condicionados a grupos específicos, como departamentos, setores ou categorias. O exemplo que compara o salário de cada funcionário com a média salarial de seu próprio departamento demonstra claramente essa capacidade, permitindo que cada registro seja avaliado considerando apenas o conjunto de dados ao qual pertence. Essa abordagem produz análises muito mais precisas do que aquelas baseadas em médias globais e representa uma técnica amplamente utilizada em sistemas corporativos, aplicações financeiras e processos de Business Intelligence.

Outro aspecto importante apresentado no documento é a demonstração de que problemas resolvidos por subconsultas correlatas também podem ser implementados utilizando junções e agregações. Essa comparação evidencia que a linguagem SQL oferece diferentes estratégias para produzir os mesmos resultados, permitindo ao profissional escolher a alternativa mais adequada conforme critérios de desempenho, facilidade de manutenção, clareza do código e otimização das consultas. O conhecimento dessas alternativas amplia significativamente a capacidade técnica do desenvolvedor e contribui para a construção de soluções mais eficientes.

O material também evidencia que as subconsultas correlatas não se limitam às consultas de seleção. Sua aplicação em comandos UPDATE demonstra que esse recurso pode ser utilizado para modificar dados de maneira inteligente e contextualizada, atualizando cada registro com base em informações calculadas dinamicamente durante a execução da própria consulta. Essa funcionalidade torna as subconsultas correlatas extremamente valiosas para processos de manutenção de dados, padronização de informações, sincronização entre registros e implementação de regras de negócio diretamente no banco de dados.

Em síntese, o conteúdo demonstra que as subconsultas correlatas constituem um dos recursos mais avançados e versáteis da linguagem SQL. Sua capacidade de relacionar consultas internas aos registros processados pela consulta principal permite desenvolver soluções robustas, flexíveis e altamente eficientes para análise e manipulação de dados. O domínio dessa técnica representa uma competência essencial para desenvolvedores, administradores de banco de dados, engenheiros de dados, analistas de dados e demais profissionais que atuam com bancos de dados relacionais e aplicações corporativas modernas.
