# Subconsultas aninhadas
O projeto está disponível em: [Subconsultas aninhadas](./Nested_Subqueries.docx)

# Resumo
O material apresenta o conceito de subconsultas aninhadas no PostgreSQL, demonstrando como consultas SQL podem utilizar o resultado de outras consultas para recuperar informações mais complexas e realizar análises detalhadas sobre os dados armazenados em bancos relacionais. Inicialmente, o documento explica que toda consulta SQL produz uma tabela como resultado, ainda que temporariamente armazenada em memória, e que esse resultado pode servir como entrada para outra consulta. Esse mecanismo recebe o nome de subconsulta e representa um dos recursos mais importantes da linguagem SQL para resolver problemas que exigem múltiplas etapas de processamento. O conteúdo diferencia ainda dois tipos principais de subconsultas: as subconsultas aninhadas, nas quais a consulta externa utiliza o resultado produzido por uma consulta interna, e as subconsultas correlatas, em que a consulta interna depende diretamente dos valores processados pela consulta externa.

Para demonstrar esses conceitos, o documento cria as tabelas DEPARTAMENTO e FUNCIONARIO, estabelecendo um relacionamento de um para muitos por meio da chave estrangeira CODIGODEPARTAMENTO. Após a criação das estruturas, são inseridos registros representando departamentos como Tecnologia da Informação, Contabilidade e Marketing, bem como diversos funcionários contendo informações sobre nome, sexo, data de nascimento, salário e departamento ao qual pertencem. Essa base de dados serve como ambiente para a execução dos exemplos apresentados ao longo do material.

Na primeira aplicação prática, é desenvolvida uma subconsulta responsável por localizar o maior salário existente na tabela FUNCIONARIO utilizando a função MAX(). O valor retornado pela consulta interna é utilizado pela consulta principal na cláusula WHERE para identificar o funcionário que recebe o maior salário da empresa. O documento explica detalhadamente que o PostgreSQL executa inicialmente a subconsulta, armazena seu resultado temporariamente e somente depois executa a consulta principal utilizando esse valor como critério de comparação. Esse exemplo demonstra claramente o fluxo de execução das subconsultas aninhadas.

Em seguida, o material apresenta uma consulta destinada a identificar os funcionários cujo salário é superior à média salarial da organização. Para isso, a subconsulta calcula a média dos salários utilizando a função AVG(), enquanto a consulta principal recupera apenas os registros cujo salário seja maior que esse valor médio. Esse exemplo evidencia como funções de agregação podem ser utilizadas em conjunto com subconsultas para produzir análises estatísticas sem a necessidade de cálculos realizados externamente ao banco de dados. 

Posteriormente, o documento apresenta uma consulta mais complexa envolvendo duas subconsultas aninhadas. O objetivo consiste em localizar os funcionários cujo salário seja inferior à média salarial dos colaboradores pertencentes ao departamento de Tecnologia da Informação. Para isso, uma subconsulta recupera inicialmente o código do departamento de TI, enquanto outra calcula a média salarial apenas dos funcionários pertencentes a esse departamento. O resultado final é utilizado pela consulta principal para selecionar os colaboradores que recebem salários inferiores à média obtida. O material demonstra ainda que essa mesma consulta pode ser reescrita utilizando uma junção entre as tabelas FUNCIONARIO e DEPARTAMENTO, produzindo exatamente o mesmo resultado e evidenciando diferentes estratégias para resolver um mesmo problema utilizando SQL.

Por fim, é apresentada uma consulta que contabiliza quantos funcionários recebem salário inferior ao maior salário entre todas as colaboradoras do sexo feminino. Nesse exemplo, a subconsulta utiliza a função MAX() para identificar o maior salário feminino existente na tabela FUNCIONARIO. Em seguida, a consulta principal utiliza esse valor como referência para contar, por meio da função COUNT(), quantos funcionários recebem menos do que esse salário. Esse último exemplo demonstra como subconsultas aninhadas podem ser combinadas com funções estatísticas para produzir indicadores quantitativos relevantes para análises organizacionais e geração de relatórios gerenciais. 

# Conclusão
O estudo sobre subconsultas aninhadas evidencia um dos recursos mais poderosos da linguagem SQL para construção de consultas complexas em bancos de dados relacionais. Ao permitir que uma consulta utilize diretamente o resultado produzido por outra consulta, esse mecanismo amplia significativamente a capacidade de recuperação e análise das informações armazenadas no banco de dados. Essa abordagem possibilita resolver problemas que seriam muito mais difíceis ou até inviáveis utilizando apenas consultas simples, tornando as subconsultas um recurso indispensável para o desenvolvimento de aplicações modernas baseadas em dados.

Ao longo do material, observa-se que as subconsultas aninhadas seguem um fluxo de execução bem definido: inicialmente o PostgreSQL executa a consulta mais interna, obtém seu resultado e, posteriormente, utiliza esse valor para avaliar as condições existentes na consulta principal. Esse comportamento torna possível realizar comparações envolvendo funções de agregação como MAX(), AVG() e COUNT(), permitindo identificar funcionários com maior salário, colaboradores que recebem acima ou abaixo da média e diversos outros indicadores estatísticos utilizados em ambientes corporativos. 

Outro aspecto importante apresentado no documento é a demonstração de que um mesmo problema pode ser resolvido por diferentes abordagens. O exemplo envolvendo a média salarial do departamento de Tecnologia da Informação mostra que uma subconsulta aninhada pode ser substituída por uma junção entre tabelas, produzindo exatamente o mesmo resultado. Essa comparação evidencia que o domínio de diferentes técnicas da linguagem SQL permite ao profissional escolher a solução mais adequada considerando critérios como legibilidade, desempenho, manutenção e padronização do código desenvolvido.

Sob a perspectiva profissional, compreender o funcionamento das subconsultas representa uma competência essencial para desenvolvedores de software, administradores de banco de dados, analistas de dados, engenheiros de dados e especialistas em Business Intelligence. Grande parte das consultas utilizadas em sistemas empresariais depende da combinação de múltiplas etapas de processamento, envolvendo cálculos estatísticos, filtros condicionais e recuperação de informações relacionadas. O domínio das subconsultas permite construir soluções mais robustas, reduzir o processamento realizado pelas aplicações e aproveitar melhor a capacidade analítica oferecida pelos sistemas gerenciadores de bancos de dados.

Em síntese, o material demonstra que as subconsultas aninhadas constituem uma ferramenta indispensável para consultas SQL de maior complexidade. Sua capacidade de reutilizar resultados intermediários, integrar funções de agregação, realizar comparações dinâmicas e substituir procedimentos externos torna esse recurso fundamental para a construção de consultas eficientes, organizadas e alinhadas às necessidades de análise presentes nos bancos de dados relacionais utilizados em ambientes corporativos e projetos modernos de tecnologia da informação.
