# SQL para Remoção de Linhas em Tabela
O projeto está disponível em: [SQL para Remoção de Linhas em Tabela](./SQL_Deleting_Rows_Into_Table.docx)

# Resumo

Este material apresenta os principais conceitos relacionados à remoção de registros em tabelas utilizando o comando DELETE da linguagem SQL no PostgreSQL. Inicialmente, o documento explica que a operação de exclusão faz parte da Linguagem de Manipulação de Dados (DML – Data Manipulation Language) e é responsável por remover registros armazenados em tabelas de um banco de dados relacional. O conteúdo destaca que o PostgreSQL permite realizar exclusões de forma seletiva por meio da utilização de condições, garantindo que apenas os registros desejados sejam eliminados. Além disso, enfatiza que o sistema oferece mecanismos para preservar a integridade dos dados durante essas operações, evitando inconsistências entre tabelas relacionadas.

Na sequência, o documento apresenta a sintaxe básica do comando DELETE, explicando que sua estrutura é composta pelo nome da tabela que sofrerá a exclusão e, opcionalmente, pela cláusula WHERE, utilizada para definir quais registros serão removidos. O material ressalta que o uso da cláusula WHERE é altamente recomendado, pois permite limitar a exclusão apenas aos registros selecionados, evitando a remoção acidental de todos os dados armazenados na tabela. Para exemplificar o funcionamento do comando, são apresentados casos práticos de exclusão de disciplinas específicas utilizando a chave primária como critério de seleção, demonstrando como o PostgreSQL localiza o registro correspondente antes de realizar sua remoção.

O conteúdo também aborda um cenário envolvendo tabelas relacionadas por chaves estrangeiras, demonstrando que o PostgreSQL impede automaticamente a exclusão de registros que são referenciados por outras tabelas. Como exemplo, é apresentada a tentativa de remover uma disciplina que ainda possui registros associados na tabela CURSODISCIPLINA. O documento explica que o Sistema Gerenciador de Banco de Dados bloqueia essa operação para preservar a integridade referencial, evitando que permaneçam registros órfãos ou referências inválidas no banco de dados. Para permitir esse tipo de exclusão, o material demonstra como alterar a definição da chave estrangeira utilizando o comando ALTER TABLE, removendo a restrição existente e recriando-a com a opção ON DELETE CASCADE, que faz com que os registros dependentes sejam removidos automaticamente quando o registro principal for excluído.

Por fim, o documento apresenta um procedimento para eliminar todos os registros das tabelas de um banco de dados respeitando as dependências existentes entre elas. O conteúdo explica que a ordem de execução dos comandos DELETE deve considerar os relacionamentos estabelecidos por chaves estrangeiras, iniciando pelas tabelas mais dependentes e prosseguindo para as tabelas independentes. Como exemplo, é demonstrada a exclusão dos registros da tabela CURSODISCIPLINA, seguida das tabelas CURSO e DISCIPLINA, evidenciando a importância de compreender a estrutura relacional do banco de dados para realizar operações de remoção de forma segura e consistente.

# Conclusão
O conteúdo apresentado demonstra que o comando DELETE desempenha um papel essencial na administração e manutenção de bancos de dados relacionais, permitindo remover registros de maneira controlada e segura. A correta utilização da cláusula WHERE garante que apenas os registros desejados sejam excluídos, reduzindo significativamente o risco de perda acidental de informações. Dessa forma, o documento evidencia que a exclusão de dados deve ser realizada de forma criteriosa, considerando sempre os impactos que essa operação pode causar sobre as informações armazenadas no banco de dados.

Outro aspecto relevante abordado é o mecanismo de proteção implementado pelo PostgreSQL por meio das restrições de integridade referencial. Ao impedir a exclusão de registros que ainda são referenciados por outras tabelas, o sistema garante que os relacionamentos definidos durante a modelagem do banco de dados permaneçam consistentes, evitando a criação de registros órfãos e preservando a confiabilidade das informações armazenadas. O estudo da opção ON DELETE CASCADE demonstra que o PostgreSQL também oferece recursos para automatizar a remoção dos registros dependentes quando essa funcionalidade é desejada, simplificando operações de exclusão em bancos de dados relacionais.

O material também evidencia que operações de remoção envolvendo múltiplas tabelas exigem planejamento e conhecimento da estrutura de relacionamentos existente no banco de dados. A necessidade de excluir inicialmente os registros das tabelas dependentes e, posteriormente, das tabelas principais reforça a importância de compreender o funcionamento das chaves estrangeiras e da integridade referencial antes de executar comandos de exclusão em ambientes reais. Esse cuidado contribui para evitar erros durante a administração do banco de dados e assegura que todas as operações sejam executadas de maneira consistente.

Em conjunto, os conceitos apresentados fornecem uma base sólida para compreender o funcionamento das operações de remoção de dados no PostgreSQL, abordando tanto a sintaxe do comando DELETE quanto os mecanismos utilizados pelo sistema para proteger a integridade das informações durante o processo de exclusão. O domínio desses recursos representa um conhecimento essencial para desenvolvedores e administradores de bancos de dados, permitindo realizar operações de manutenção de forma segura, eficiente e alinhada às boas práticas de gerenciamento de bancos de dados relacionais.
