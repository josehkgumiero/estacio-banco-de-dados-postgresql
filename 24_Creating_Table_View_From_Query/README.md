# Criando tabela e view a partir de consulta
O projeto está disponível em: [Funções de resumo ou de agregação](./Creating_Table_View_From_Query.docx)

# Resumo
O documento apresenta os conceitos e procedimentos para criar tabelas e views (visões) a partir de consultas SQL no PostgreSQL, demonstrando como transformar o resultado de um comando SELECT em novos objetos do banco de dados. Inicialmente, o material destaca que esse recurso é amplamente utilizado durante o desenvolvimento de aplicações e projetos de banco de dados, pois permite estruturar informações derivadas de consultas complexas de forma organizada, reutilizável e eficiente. A criação desses objetos facilita a construção de bases de dados voltadas para análises, relatórios e processamento de informações, reduzindo a necessidade de reescrever consultas repetidamente e contribuindo para a padronização do acesso aos dados.

O primeiro conceito abordado é a criação de tabelas a partir de consultas, utilizando a instrução CREATE TABLE ... AS SELECT. O documento explica que essa técnica possibilita armazenar permanentemente o resultado de uma consulta em uma nova tabela física do banco de dados. Diferentemente de uma consulta convencional, cujo resultado existe apenas durante sua execução, a nova tabela passa a armazenar os dados recuperados pela consulta, podendo ser utilizada posteriormente em outras operações SQL, como novas consultas, atualizações, exclusões ou integrações com outras tabelas. Essa funcionalidade é especialmente útil quando há necessidade de criar tabelas temporárias para processamento, consolidar dados provenientes de diferentes fontes ou preservar o resultado de consultas complexas para reutilização futura.

Para exemplificar esse processo, o documento utiliza a tabela ALUNO, aplicando funções estudadas anteriormente, como AGE(), EXTRACT() e a estrutura condicional CASE, para calcular a idade dos alunos e classificá-los em diferentes faixas etárias. O resultado dessa consulta é armazenado em uma nova tabela denominada TTESTE, contendo apenas as informações relevantes para essa análise. O exemplo demonstra que a criação da tabela não apenas copia dados existentes, mas também permite armazenar informações derivadas e calculadas durante a execução da consulta, agregando valor ao processo de organização dos dados e reduzindo a necessidade de recalcular essas informações em consultas futuras.

Na sequência, o documento apresenta o conceito de view (visão), um objeto lógico do banco de dados que representa uma consulta armazenada. Diferentemente da tabela criada por meio de CREATE TABLE AS, a view não armazena fisicamente os dados consultados; ela registra apenas a definição da consulta SQL. Sempre que uma view é consultada, o PostgreSQL executa novamente a consulta associada, retornando dados atualizados das tabelas de origem. Essa característica torna as views extremamente úteis para encapsular consultas complexas, simplificar o acesso às informações, padronizar relatórios e restringir a visualização de determinados dados, oferecendo uma camada adicional de abstração entre as tabelas físicas e os usuários ou aplicações que consomem essas informações.

O exemplo apresentado para criação da view VTESTE reutiliza exatamente a mesma lógica aplicada na criação da tabela, calculando a idade dos alunos e classificando-os em faixas etárias por meio das funções AGE(), EXTRACT() e da estrutura CASE. Entretanto, nesse caso, os dados permanecem vinculados diretamente à tabela ALUNO, refletindo automaticamente qualquer alteração realizada nos registros originais. Dessa forma, o documento evidencia a principal diferença entre tabelas criadas a partir de consultas e views: enquanto a tabela armazena uma cópia dos resultados existentes no momento da criação, a view mantém uma representação dinâmica da consulta, exibindo sempre informações atualizadas.

Ao longo do material, fica evidente que tanto as tabelas derivadas quanto as views representam mecanismos importantes para otimizar o desenvolvimento de aplicações, melhorar a organização das consultas SQL e facilitar a reutilização de estruturas de dados em diferentes contextos. Esses recursos são amplamente empregados em sistemas corporativos, ambientes de Business Intelligence, Engenharia de Dados e Ciência de Dados, onde consultas complexas precisam ser reutilizadas diversas vezes, garantindo maior produtividade, padronização e manutenção simplificada dos bancos de dados.
# Conclusão
O estudo da criação de tabelas e views a partir de consultas SQL demonstra como o PostgreSQL oferece recursos capazes de ampliar significativamente a reutilização e a organização das informações armazenadas em bancos de dados relacionais. A utilização do comando CREATE TABLE AS SELECT permite transformar o resultado de consultas em novas tabelas físicas, preservando dados derivados, simplificando processos de análise e reduzindo o custo computacional de consultas que precisariam ser executadas repetidamente. Esse recurso é particularmente útil em processos de consolidação de dados, criação de tabelas intermediárias para ETL, preparação de bases analíticas e armazenamento de resultados provenientes de cálculos complexos.

O documento também evidencia a importância das views como mecanismo de abstração e reutilização de consultas SQL. Ao encapsular a lógica de uma consulta em um objeto lógico do banco de dados, as views simplificam o acesso às informações, reduzem a duplicação de código SQL e promovem maior padronização no desenvolvimento de aplicações. Como os dados apresentados por uma view são obtidos diretamente das tabelas de origem sempre que a consulta é executada, esse recurso garante que as informações permaneçam atualizadas sem necessidade de replicação física dos registros, tornando-se uma solução eficiente para relatórios, dashboards e consultas frequentemente reutilizadas.

Outro aspecto importante apresentado pelo material é a integração entre diversos recursos estudados anteriormente, como as funções AGE(), EXTRACT() e a estrutura condicional CASE. A utilização conjunta dessas funcionalidades demonstra que tanto tabelas derivadas quanto views podem armazenar ou representar informações calculadas durante a execução das consultas, permitindo construir estruturas de dados mais ricas e alinhadas às necessidades do negócio. Essa capacidade amplia significativamente o potencial da linguagem SQL para o desenvolvimento de soluções analíticas e sistemas de apoio à decisão, nos quais dados derivados desempenham papel fundamental na geração de indicadores e métricas gerenciais.

Em síntese, o documento estabelece uma base sólida para compreender quando utilizar tabelas derivadas e quando optar pela criação de views, evidenciando que ambos os recursos possuem finalidades distintas e complementares. Enquanto as tabelas criadas por consultas são indicadas para armazenar resultados permanentes e independentes das tabelas originais, as views são mais adequadas para representar consultas reutilizáveis e manter acesso dinâmico aos dados atualizados. O domínio dessas técnicas prepara o profissional para desenvolver bancos de dados mais organizados, escaláveis e eficientes, além de fornecer fundamentos importantes para temas mais avançados relacionados à modelagem de dados, otimização de consultas, Data Warehousing, Engenharia de Dados e Business Intelligence.
