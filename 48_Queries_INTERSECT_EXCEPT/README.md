# Consultas com os operadores INTERSECT e EXCEPT
O projeto está disponível em: [Consultas com os operadores INTERSECT e EXCEPT](./Queries_INTERSECT_EXCEPT.docx)

# Resumo
O material apresenta os operadores INTERSECT e EXCEPT no PostgreSQL, demonstrando como esses recursos permitem comparar conjuntos de dados provenientes de diferentes consultas SQL. Inicialmente, o documento explica que o operador INTERSECT é responsável por retornar apenas as linhas que aparecem simultaneamente nos resultados de duas ou mais consultas. Para que a operação seja executada corretamente, todas as consultas participantes devem possuir a mesma quantidade de colunas e compatibilidade entre seus tipos de dados. Além disso, o operador elimina automaticamente registros duplicados, retornando apenas valores distintos presentes em todos os conjuntos analisados. Sua sintaxe geral também permite o uso das opções ALL e DISTINCT, embora o comportamento padrão seja a eliminação das duplicidades.

O primeiro exemplo prático utiliza as tabelas FUNCIONARIO e CLIENTE para identificar todos os cidadãos que pertencem simultaneamente aos dois conjuntos de dados. A consulta recupera os campos NOME e CPF de ambas as tabelas utilizando o operador INTERSECT, retornando apenas os registros existentes nas duas tabelas. O documento demonstra que três pessoas aparecem simultaneamente como funcionários e clientes, ilustrando claramente o conceito matemático de interseção entre conjuntos aplicado ao contexto dos bancos de dados relacionais.

Na sequência, o conteúdo amplia a consulta para envolver três tabelas simultaneamente: FUNCIONARIO, CLIENTE e ALUNO. Utilizando duas operações INTERSECT consecutivas, a consulta identifica apenas os cidadãos que pertencem aos três conjuntos de dados ao mesmo tempo. Como resultado, apenas dois registros satisfazem essa condição. O material também explica a precedência entre operadores de conjunto, destacando que uma expressão escrita no formato X UNION Y INTERSECT Z é interpretada como X UNION (Y INTERSECT Z), evidenciando a importância da ordem de execução das operações durante o processamento da consulta SQL.

Posteriormente, o documento introduz o operador EXCEPT, responsável por implementar a operação de diferença entre conjuntos. Diferentemente do INTERSECT, que retorna apenas os elementos comuns, o EXCEPT devolve os registros presentes na primeira consulta e ausentes na segunda. Assim como os demais operadores de conjunto, as consultas participantes devem possuir estruturas compatíveis e registros duplicados são eliminados automaticamente do resultado. O material também informa que alguns sistemas gerenciadores de bancos de dados utilizam o operador MINUS para representar a mesma operação, como ocorre no Oracle Database. 

Os exemplos envolvendo EXCEPT demonstram inicialmente como identificar funcionários que não são clientes. A consulta retorna apenas os registros existentes na tabela FUNCIONARIO que não aparecem na tabela CLIENTE, produzindo duas linhas como resultado. Em seguida, o documento apresenta a operação inversa, CLIENTE EXCEPT FUNCIONARIO, demonstrando que o resultado é vazio porque todos os clientes cadastrados também pertencem ao conjunto de funcionários. Esse exemplo evidencia que o operador EXCEPT não é comutativo, ou seja, a ordem das consultas altera completamente o resultado produzido.

Por fim, o material apresenta uma consulta envolvendo três operações EXCEPT consecutivas. O objetivo consiste em identificar os cidadãos que pertencem exclusivamente ao conjunto de funcionários, excluindo aqueles que também são clientes e, posteriormente, aqueles que também são alunos. Essa consulta demonstra como múltiplas operações de diferença podem ser combinadas para construir filtros cada vez mais específicos, permitindo identificar registros exclusivos de determinado conjunto de dados e ampliar as possibilidades de análise em bancos de dados relacionais.

# Conclusão

O estudo dos operadores INTERSECT e EXCEPT amplia significativamente o domínio da linguagem SQL ao introduzir recursos voltados à comparação entre conjuntos de dados. Enquanto o operador INTERSECT permite identificar registros comuns entre duas ou mais consultas, o operador EXCEPT possibilita localizar registros exclusivos de determinado conjunto, excluindo aqueles presentes em outro. Esses operadores representam importantes aplicações da teoria dos conjuntos em bancos de dados relacionais, oferecendo soluções elegantes e eficientes para problemas de comparação e consolidação de informações provenientes de diferentes fontes.

Ao longo do material, observa-se que o operador INTERSECT constitui uma ferramenta extremamente útil para identificar elementos compartilhados entre diferentes tabelas. Os exemplos envolvendo funcionários, clientes e alunos demonstram claramente sua aplicação na identificação de registros comuns entre múltiplos conjuntos de dados, sendo especialmente útil em processos de integração de sistemas, validação cadastral, cruzamento de informações e auditorias de dados. Além disso, o conteúdo destaca a importância da precedência entre operadores de conjunto, evidenciando que a correta interpretação da ordem de execução influencia diretamente os resultados obtidos pelas consultas SQL.

O operador EXCEPT, por sua vez, oferece uma solução eficiente para identificar registros exclusivos de determinado conjunto de dados. Os exemplos apresentados demonstram que sua principal finalidade consiste em realizar operações de diferença entre consultas, permitindo localizar funcionários que não são clientes, clientes que não pertencem ao conjunto de funcionários ou cidadãos exclusivos de apenas um dos grupos analisados. O documento também evidencia que EXCEPT não é uma operação comutativa, reforçando a importância da ordem das consultas para obtenção do resultado esperado.

Sob a perspectiva profissional, dominar INTERSECT e EXCEPT representa uma competência relevante para desenvolvedores, administradores de banco de dados, engenheiros de dados, analistas de dados e especialistas em Business Intelligence. Esses operadores são amplamente empregados em processos de integração de bases de dados, auditorias, migração de sistemas, validação de informações, identificação de inconsistências cadastrais e desenvolvimento de consultas analíticas voltadas ao apoio à tomada de decisão. Seu uso adequado contribui para a construção de consultas mais organizadas, legíveis e eficientes.

Em síntese, o material demonstra que INTERSECT e EXCEPT constituem operadores fundamentais da linguagem SQL para comparação entre conjuntos de dados. Ao possibilitar a identificação de registros comuns e exclusivos entre diferentes consultas, esses recursos ampliam significativamente a capacidade analítica dos bancos de dados relacionais e oferecem soluções robustas para integração, validação e análise de informações em aplicações modernas e ambientes corporativos orientados por dados.
