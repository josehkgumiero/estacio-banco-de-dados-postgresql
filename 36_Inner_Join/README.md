# Junção interna
O projeto está disponível em: [Junção interna](./Inner_Join.docx)

# Resumo
O material apresenta o conceito de junção interna (INNER JOIN) no PostgreSQL, demonstrando sua importância na recuperação de informações armazenadas em diferentes tabelas de um banco de dados relacional. Inicialmente, o documento explica que o objetivo das junções internas é combinar registros relacionados entre tabelas distintas, permitindo extrair apenas informações que realmente possuem correspondência entre si. Esse recurso representa uma das operações mais utilizadas na linguagem SQL, pois possibilita construir consultas precisas, eficientes e compatíveis com a estrutura relacional dos bancos de dados modernos.

Para exemplificar o funcionamento do INNER JOIN, o material utiliza as tabelas CURSO e NIVEL, anteriormente criadas e relacionadas pela coluna CODIGONIVEL. O documento demonstra que, ao analisar o resultado obtido por meio do produto cartesiano, apenas algumas combinações representam fatos reais cadastrados no banco de dados. As demais linhas surgem apenas porque todas as combinações possíveis entre as tabelas foram realizadas, independentemente da existência de relacionamento entre os registros. Dessa forma, torna-se necessário aplicar uma condição de igualdade entre a chave primária da tabela NIVEL e a chave estrangeira da tabela CURSO para eliminar as combinações incorretas. 

Inicialmente, essa filtragem é realizada utilizando a cláusula WHERE, por meio da consulta SELECT * FROM CURSO, NIVEL WHERE NIVEL.CODIGONIVEL = CURSO.CODIGONIVEL. Essa consulta retorna apenas os registros que possuem correspondência entre as duas tabelas, eliminando automaticamente todas as combinações inválidas produzidas pelo produto cartesiano. Embora essa abordagem produza o resultado esperado, o documento ressalta que atualmente a forma mais utilizada consiste no emprego da cláusula INNER JOIN, cuja sintaxe torna a consulta mais organizada, legível e alinhada aos padrões modernos da linguagem SQL. 

Na sequência, o conteúdo apresenta a sintaxe geral da junção interna, explicando que a cláusula INNER JOIN deve ser acompanhada da palavra-chave ON, responsável por definir a condição de relacionamento entre as tabelas. Em situações típicas, essa condição estabelece a igualdade entre uma chave primária e sua respectiva chave estrangeira. O documento demonstra que essa sintaxe facilita a compreensão da consulta, tornando explícita a relação existente entre as tabelas envolvidas na operação.

O material também apresenta a utilização da cláusula USING, um recurso disponível quando ambas as tabelas possuem uma coluna com o mesmo nome utilizada no relacionamento. Nesse caso, basta informar o nome da coluna compartilhada, simplificando a escrita da consulta e reduzindo a necessidade de repetir explicitamente a condição de igualdade entre as tabelas. Essa alternativa torna o código mais limpo e de fácil manutenção, preservando exatamente o mesmo resultado obtido com a cláusula ON.

Outro aspecto abordado refere-se à seleção específica de colunas. Em vez de utilizar SELECT *, o documento demonstra como recuperar apenas as informações realmente necessárias, como código e nome do curso, juntamente com o código e a descrição do nível correspondente. Para isso, é utilizada a notação completa NOMETABELA.NOMECOLUNA, permitindo identificar claramente a origem de cada atributo. Essa prática evita ambiguidades quando diferentes tabelas possuem colunas com o mesmo nome e contribui para uma melhor organização das consultas SQL. 

Por fim, o conteúdo apresenta o uso de apelidos (aliases) para as tabelas, substituindo seus nomes completos por identificadores menores, como C para CURSO e N para NIVEL. Essa técnica reduz o tamanho da consulta, melhora sua legibilidade e facilita a escrita de comandos SQL mais extensos envolvendo diversas tabelas. O exemplo final demonstra uma consulta completa utilizando aliases, INNER JOIN e seleção específica de colunas, evidenciando uma forma profissional de construir consultas relacionais no PostgreSQL.

# Conclusão
O estudo sobre junção interna (INNER JOIN) demonstra um dos conceitos mais importantes da linguagem SQL e dos bancos de dados relacionais. A capacidade de combinar informações provenientes de diferentes tabelas constitui a base para o desenvolvimento de consultas utilizadas em praticamente todos os sistemas corporativos, permitindo transformar dados distribuídos em diferentes estruturas em informações completas, consistentes e úteis para os usuários. O material evidencia que o INNER JOIN representa a forma mais eficiente e organizada de recuperar apenas os registros que realmente possuem relacionamento entre si. 

Ao longo do conteúdo, observa-se claramente a diferença entre o produto cartesiano e a junção interna. Enquanto o produto cartesiano combina indiscriminadamente todos os registros das tabelas envolvidas, produzindo inúmeras combinações sem significado prático, o INNER JOIN aplica uma condição de igualdade entre as colunas relacionadas, eliminando automaticamente todas as combinações inválidas. Essa característica melhora significativamente tanto a qualidade dos resultados quanto o desempenho das consultas executadas pelo banco de dados.

Outro aspecto relevante abordado no documento refere-se às diferentes formas de implementar uma junção interna. Além da utilização da cláusula ON para definir explicitamente a condição de relacionamento entre as tabelas, o PostgreSQL oferece a cláusula USING, que simplifica a sintaxe quando ambas as tabelas compartilham uma coluna de mesmo nome. O material também destaca boas práticas de programação SQL, como a seleção apenas das colunas necessárias e o uso de aliases para identificar tabelas, tornando as consultas mais organizadas, legíveis e fáceis de manter.

Sob a perspectiva profissional, dominar o INNER JOIN representa uma competência indispensável para desenvolvedores de software, administradores de banco de dados, analistas de dados, engenheiros de dados e cientistas de dados. Grande parte das consultas utilizadas em sistemas empresariais depende da integração de informações provenientes de diferentes tabelas, tornando essencial compreender como definir corretamente os relacionamentos, selecionar atributos específicos e estruturar consultas eficientes utilizando boas práticas de desenvolvimento.

Em síntese, o material demonstra que a junção interna constitui o principal mecanismo de integração de dados em bancos de dados relacionais. Ao relacionar tabelas por meio de chaves primárias e estrangeiras, o INNER JOIN permite recuperar apenas informações consistentes e relacionadas, eliminando combinações incorretas produzidas pelo produto cartesiano. Dessa forma, o domínio dessa técnica representa um passo fundamental para a construção de consultas SQL robustas, otimizadas e adequadas às necessidades dos sistemas modernos e das aplicações orientadas por dados.
