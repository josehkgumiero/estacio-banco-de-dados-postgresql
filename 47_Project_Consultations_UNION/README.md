# Projeto consultas com o operador UNION
O projeto está disponível em: [Projeto consultas com o operador UNION](./Project_Consultations_UNION.docx)

# Resumo
O material apresenta um projeto prático sobre o operador UNION no PostgreSQL utilizando o banco de dados do museu como ambiente de aplicação. O objetivo principal é consolidar os conhecimentos adquiridos sobre os operadores UNION e UNION ALL por meio da construção de consultas SQL capazes de combinar resultados provenientes de diferentes tabelas. Inicialmente, o documento apresenta o modelo lógico do banco de dados do museu e propõe um roteiro de exercícios envolvendo salões, obras, autores, pinturas, esculturas e alocações. As atividades foram elaboradas para demonstrar, de forma prática, as diferenças entre UNION e UNION ALL, bem como sua aplicação em consultas que integram informações de diferentes entidades do banco de dados.

A primeira atividade consiste em listar os números dos salões que possuem obras cadastradas ou que possuem funcionários alocados. Para resolver esse problema, são realizadas duas consultas independentes: uma recupera os números dos salões presentes na tabela OBRAS, enquanto a outra obtém os números dos salões registrados na tabela ALOCACOES. Os resultados são combinados utilizando o operador UNION, que elimina automaticamente registros duplicados, retornando apenas uma ocorrência de cada salão, mesmo quando ele aparece simultaneamente nas duas consultas. Esse exemplo evidencia o comportamento padrão do operador UNION na remoção automática de duplicidades.

Na sequência, o documento apresenta exatamente a mesma consulta utilizando o operador UNION ALL. Nesse caso, diferentemente do UNION, todos os registros produzidos pelas duas consultas são preservados, incluindo aqueles que aparecem repetidamente em ambas as tabelas. O exemplo demonstra claramente que o UNION ALL simplesmente concatena os resultados das consultas sem realizar qualquer verificação de duplicidade, tornando-se uma alternativa adequada quando todas as ocorrências precisam ser mantidas no resultado final ou quando se busca maior desempenho na execução da consulta.

O terceiro exercício amplia a aplicação dos operadores de conjunto ao recuperar os códigos das obras classificadas como pinturas impressionistas ou esculturas produzidas em argila. Para isso, são realizadas duas consultas distintas: a primeira recupera os códigos das pinturas cujo estilo seja "Impressionista", enquanto a segunda retorna os códigos das esculturas confeccionadas em argila. Os resultados são unidos por meio do operador UNION, garantindo que códigos repetidos sejam exibidos apenas uma única vez caso uma mesma obra satisfaça ambas as condições estabelecidas. Em seguida, o documento apresenta a mesma consulta utilizando UNION ALL, demonstrando novamente a diferença entre eliminar ou preservar registros duplicados durante a combinação dos resultados.

Por fim, o projeto apresenta consultas mais completas envolvendo junções entre as tabelas OBRAS, AUTORES, PINTURAS e ESCULTURAS. O objetivo consiste em listar o título das obras e o nome de seus respectivos autores para todas as obras impressionistas ou confeccionadas em argila. Para isso, são realizadas duas consultas utilizando INNER JOIN, uma voltada às pinturas impressionistas e outra às esculturas de argila. Os resultados são combinados inicialmente utilizando UNION e, posteriormente, UNION ALL, permitindo comparar o comportamento de ambos os operadores em consultas envolvendo múltiplas tabelas e relacionamentos. Esse exemplo demonstra que operadores de conjunto podem ser utilizados em consultas bastante complexas, integrando informações provenientes de diferentes entidades do banco de dados de forma organizada e eficiente.

# Conclusão

O projeto prático sobre consultas utilizando o operador UNION consolida os principais conceitos relacionados aos operadores de conjunto da linguagem SQL, demonstrando como resultados provenientes de diferentes consultas podem ser combinados de maneira eficiente em bancos de dados relacionais. Utilizando o banco de dados do museu como ambiente de aplicação, o material aproxima o estudante de situações encontradas em sistemas corporativos, nas quais frequentemente é necessário integrar informações armazenadas em diferentes tabelas para produzir relatórios consolidados e análises mais abrangentes.

Ao longo do conteúdo, observa-se claramente a diferença entre os operadores UNION e UNION ALL. Enquanto o UNION elimina automaticamente registros duplicados durante a combinação dos resultados, produzindo um conjunto composto apenas por linhas distintas, o UNION ALL preserva todas as ocorrências retornadas pelas consultas participantes. Essa distinção é fundamental para que o desenvolvedor escolha corretamente o operador mais adequado conforme os requisitos da aplicação, considerando aspectos como necessidade de eliminação de duplicidades, desempenho e integridade dos resultados obtidos.

Outro aspecto relevante apresentado no projeto é a demonstração de que operadores de conjunto podem ser utilizados em consultas envolvendo múltiplas tabelas e operações de junção. Os exemplos que recuperam títulos de obras e nomes de autores evidenciam que UNION e UNION ALL não se limitam a consultas simples, podendo integrar resultados produzidos por instruções SQL complexas contendo INNER JOIN, filtros condicionais e diferentes critérios de seleção. Essa flexibilidade amplia significativamente as possibilidades de utilização desses operadores em ambientes profissionais.

Sob a perspectiva profissional, dominar os operadores UNION e UNION ALL representa uma competência essencial para desenvolvedores de software, administradores de banco de dados, analistas de dados, engenheiros de dados e especialistas em Business Intelligence. Esses operadores são amplamente empregados em processos de integração de dados, ETL, consolidação de informações provenientes de diferentes sistemas, auditorias, migração de bases de dados e geração de relatórios corporativos. Seu uso adequado contribui para consultas mais organizadas, reutilizáveis e eficientes.

Em síntese, o projeto demonstra que os operadores UNION e UNION ALL constituem recursos indispensáveis da linguagem SQL para combinação de conjuntos de dados. A correta compreensão das diferenças entre eliminação e preservação de registros duplicados, aliada à capacidade de integrar consultas simples e complexas, permite desenvolver soluções robustas e escaláveis para recuperação de informações em bancos de dados relacionais. Dessa forma, o domínio desses operadores representa uma habilidade fundamental para profissionais que atuam com desenvolvimento de sistemas, administração de bancos de dados e análise de dados em ambientes corporativos.
