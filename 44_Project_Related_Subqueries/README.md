# Projeto subconsultas correlatas
O projeto está disponível em: [Projeto subconsultas correlatas](./Project_Related_Subqueries.docx)

# Resumo
O material apresenta um projeto prático sobre subconsultas correlatas no PostgreSQL utilizando o banco de dados do museu como ambiente de aplicação dos conceitos estudados anteriormente. O objetivo principal consiste em consolidar os conhecimentos sobre subconsultas correlacionadas e operadores de teste de existência por meio da resolução de problemas reais envolvendo salões, autores, obras, pinturas e esculturas. Inicialmente, o documento apresenta o modelo lógico do banco de dados e propõe um roteiro composto por quatro exercícios que exploram comparações com médias, utilização dos operadores EXISTS e NOT EXISTS e consultas correlacionadas para comparação entre diferentes tipos de obras artísticas. Essa abordagem proporciona uma visão prática da aplicação desses recursos em bancos de dados relacionais utilizados em sistemas corporativos.

A primeira consulta proposta utiliza uma subconsulta correlacionada para identificar todos os salões cuja área seja superior à área média dos salões localizados no mesmo andar. Para isso, a consulta principal percorre cada salão existente na tabela SALOES, enquanto a subconsulta calcula dinamicamente a média da área apenas dos salões pertencentes ao mesmo andar do registro atualmente processado. Essa comparação contextualizada demonstra uma das principais características das subconsultas correlatas, nas quais o resultado da subconsulta depende diretamente dos valores da consulta principal.

Na sequência, o material apresenta exemplos utilizando o operador EXISTS. A consulta retorna todos os autores que possuem pelo menos uma obra cadastrada no museu, verificando para cada autor a existência de registros relacionados na tabela OBRAS. Em seguida, é apresentada a versão complementar utilizando NOT EXISTS, responsável por localizar apenas os autores que ainda não possuem qualquer obra cadastrada. Esses exemplos demonstram a integração entre subconsultas correlacionadas e testes de existência, permitindo verificar de forma simples e eficiente a presença ou ausência de relacionamentos entre diferentes entidades do banco de dados.

O quarto exercício amplia o nível de complexidade das consultas ao comparar a quantidade de pinturas e esculturas produzidas por cada autor. Para resolver esse problema, são utilizadas duas subconsultas correlacionadas independentes: a primeira contabiliza todas as pinturas associadas às obras de determinado autor, enquanto a segunda realiza a mesma contagem para esculturas. A consulta principal retorna apenas os autores cuja quantidade de pinturas seja superior ao número de esculturas, demonstrando como múltiplas subconsultas podem ser utilizadas simultaneamente para realizar comparações entre diferentes conjuntos de dados relacionados.

Por fim, o documento apresenta uma solução alternativa para o quarto exercício utilizando uma Common Table Expression (CTE). Nessa abordagem, uma expressão WITH denominada QUANTIDADE_OBRAS calcula previamente o total de pinturas e esculturas de cada autor utilizando LEFT JOIN, GROUP BY e funções de agregação. Posteriormente, a consulta principal apenas seleciona os autores cuja quantidade de pinturas seja superior à de esculturas. Esse exemplo demonstra que problemas resolvidos por subconsultas correlacionadas também podem ser solucionados utilizando CTEs, oferecendo ao desenvolvedor diferentes estratégias para construção de consultas SQL mais organizadas, reutilizáveis e de fácil manutenção.

# Conclusão
O projeto prático sobre subconsultas correlatas consolida os conhecimentos relacionados às consultas SQL avançadas no PostgreSQL, demonstrando como diferentes técnicas podem ser combinadas para resolver problemas complexos de recuperação e análise de dados. Ao utilizar o banco de dados do museu como cenário de aplicação, o material aproxima o estudante de situações semelhantes às encontradas em ambientes corporativos, evidenciando a importância das subconsultas correlacionadas, dos operadores EXISTS e NOT EXISTS e das expressões comuns de tabela (CTEs) na construção de consultas robustas e eficientes.

Ao longo do conteúdo, observa-se que as subconsultas correlacionadas permitem realizar comparações baseadas no contexto específico de cada registro, como ocorre na análise da área média dos salões pertencentes ao mesmo andar. Essa característica amplia significativamente a capacidade analítica da linguagem SQL, possibilitando desenvolver consultas que produzem resultados mais precisos do que aqueles obtidos por comparações baseadas em valores globais. Essa flexibilidade representa uma das principais vantagens das subconsultas correlacionadas em bancos de dados relacionais.

Outro aspecto relevante apresentado no projeto é a utilização dos operadores EXISTS e NOT EXISTS para verificar a existência ou ausência de registros relacionados. Os exemplos envolvendo autores com e sem obras demonstram que esses operadores constituem uma solução simples, eficiente e altamente legível para validar relacionamentos entre tabelas, sendo amplamente utilizados em consultas SQL voltadas à auditoria de dados, controle de integridade referencial e elaboração de relatórios gerenciais.

O material também evidencia que um mesmo problema pode ser resolvido utilizando diferentes abordagens. A comparação entre a solução baseada em subconsultas correlacionadas e a alternativa implementada por meio de uma Common Table Expression (CTE) demonstra que a linguagem SQL oferece diversas estratégias para atingir os mesmos resultados. O domínio dessas alternativas permite ao profissional escolher a implementação mais adequada conforme critérios de desempenho, clareza do código, facilidade de manutenção e padronização adotada em cada projeto.

Em síntese, o projeto demonstra que as subconsultas correlacionadas representam um recurso fundamental para o desenvolvimento de consultas SQL avançadas. Sua integração com operadores de teste de existência, funções de agregação, junções e CTEs amplia significativamente as possibilidades de análise dos dados, permitindo construir consultas flexíveis, organizadas e altamente eficientes. O domínio dessas técnicas constitui uma competência essencial para desenvolvedores, administradores de banco de dados, analistas de dados, engenheiros de dados e demais profissionais que atuam com bancos de dados relacionais e soluções corporativas orientadas por dados.
