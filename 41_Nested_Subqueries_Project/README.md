# Projeto subconsultas aninhadas
O projeto está disponível em: [Projeto subconsultas aninhadas](./Nested_Subqueries_Project.docx)

# Resumo
O material apresenta um projeto prático sobre subconsultas aninhadas no PostgreSQL utilizando o banco de dados do museu como ambiente de aprendizagem. O objetivo principal é consolidar os conceitos estudados anteriormente por meio da elaboração de consultas SQL que utilizam subconsultas para recuperar informações específicas armazenadas em diferentes tabelas do banco de dados. Inicialmente, o documento apresenta o modelo lógico do banco do museu e propõe uma sequência de exercícios envolvendo funcionários, salões, autores, obras e alocações, permitindo que o estudante desenvolva consultas baseadas em subconsultas para resolver problemas comuns encontrados em sistemas de informação.

A primeira atividade propõe identificar todos os funcionários cujo salário seja superior ao salário médio de todos os colaboradores da organização. Para resolver esse problema, a consulta principal utiliza uma subconsulta contendo a função AVG(), responsável por calcular a média salarial da tabela FUNCIONARIOS. O valor retornado pela subconsulta é utilizado na cláusula WHERE para selecionar apenas os funcionários cujo salário seja superior à média geral da empresa. Esse exemplo demonstra como funções de agregação podem ser integradas às subconsultas para produzir análises estatísticas diretamente no banco de dados.

Na sequência, o material apresenta consultas destinadas à identificação de salões que possuem ou não possuem obras expostas. Para localizar os salões que contêm obras, a consulta utiliza a cláusula IN juntamente com uma subconsulta que recupera todos os números de salões existentes na tabela OBRAS. Em seguida, é apresentada a situação inversa, utilizando a cláusula NOT IN para localizar apenas os salões que não aparecem na tabela de obras. Esses exemplos demonstram como subconsultas podem ser utilizadas para verificar a existência ou ausência de relacionamentos entre registros pertencentes a diferentes tabelas do banco de dados.

Posteriormente, o documento apresenta uma consulta voltada à identificação dos autores que não possuem obras expostas no museu. A consulta principal retorna todos os registros da tabela AUTORES cujo código não aparece na lista de autores existentes na tabela OBRAS. Para isso, é utilizada novamente a cláusula NOT IN associada a uma subconsulta responsável por recuperar os códigos dos autores que possuem obras cadastradas. Esse exemplo evidencia uma aplicação prática bastante comum das subconsultas: localizar registros órfãos ou entidades ainda não relacionadas a outras tabelas do banco de dados. 

O material também apresenta consultas relacionadas à tabela FUNCIONARIOS e à tabela ALOCACOES. Inicialmente, é utilizada a cláusula IN para recuperar todos os funcionários que possuem alguma alocação registrada. Em seguida, a cláusula NOT IN é empregada para listar apenas aqueles colaboradores que ainda não possuem qualquer alocação cadastrada. Esses exemplos reforçam o uso das subconsultas como mecanismo eficiente para identificar relacionamentos existentes ou inexistentes entre diferentes entidades do banco de dados. 

Por fim, o documento apresenta versões equivalentes das consultas utilizando os operadores EXISTS e NOT EXISTS. As consultas demonstram que, em vez de comparar listas de valores por meio das cláusulas IN e NOT IN, também é possível verificar diretamente a existência ou inexistência de registros relacionados utilizando EXISTS. São apresentados exemplos envolvendo funcionários com ou sem alocação e salões que possuem ou não possuem obras cadastradas. Essa comparação evidencia que diferentes construções da linguagem SQL podem produzir os mesmos resultados, permitindo ao desenvolvedor escolher a abordagem mais adequada conforme critérios de desempenho, legibilidade ou padronização do código.

# Conclusão

O projeto prático sobre subconsultas aninhadas consolida os principais conceitos relacionados ao uso de consultas internas na linguagem SQL, demonstrando como esse recurso pode ser empregado para resolver problemas complexos de recuperação de dados em bancos relacionais. Ao utilizar o banco de dados do museu como ambiente de prática, o material aproxima o estudante de situações reais encontradas em sistemas corporativos, evidenciando que muitas consultas dependem da reutilização dos resultados produzidos por outras consultas para gerar informações mais precisas e relevantes.

Ao longo do conteúdo, observa-se que as subconsultas permitem construir filtros dinâmicos baseados em funções estatísticas, listas de valores e relacionamentos entre diferentes tabelas. Os exemplos envolvendo salários superiores à média, identificação de salões com ou sem obras, autores sem obras cadastradas e funcionários com ou sem alocação demonstram que as subconsultas representam uma ferramenta extremamente versátil para solucionar problemas de análise de dados sem a necessidade de processamento adicional pelas aplicações externas. 

Outro aspecto importante apresentado no projeto é a comparação entre diferentes formas de implementar consultas equivalentes. Além do uso das cláusulas IN e NOT IN, o documento demonstra que os operadores EXISTS e NOT EXISTS podem produzir exatamente os mesmos resultados ao verificar diretamente a existência de registros relacionados. Essa comparação amplia o conhecimento do estudante sobre alternativas disponíveis na linguagem SQL e evidencia que a escolha entre essas abordagens pode considerar fatores como desempenho, clareza da consulta e boas práticas de desenvolvimento.

Sob a perspectiva profissional, dominar o uso de subconsultas, IN, NOT IN, EXISTS e NOT EXISTS constitui uma competência essencial para desenvolvedores de software, administradores de banco de dados, analistas de dados, engenheiros de dados e especialistas em Business Intelligence. Grande parte das consultas utilizadas em sistemas empresariais exige a verificação da existência de relacionamentos, comparação de conjuntos de registros e aplicação de filtros baseados em resultados intermediários, tornando esses recursos indispensáveis para a construção de consultas eficientes e escaláveis.

Em síntese, o projeto demonstra que as subconsultas aninhadas representam uma das ferramentas mais importantes da linguagem SQL para análise de dados em bancos relacionais. Sua integração com operadores como IN, NOT IN, EXISTS e NOT EXISTS amplia significativamente as possibilidades de recuperação de informações, permitindo desenvolver consultas robustas, organizadas e capazes de atender às necessidades de sistemas modernos, processos analíticos e aplicações corporativas orientadas por dados.
